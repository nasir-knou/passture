# 데이터세트 검토 가이드

새 출처를 입력한 뒤 적대적 검증과 최종 검증에 쓰는 기준. 입력 규칙 자체는 [data-schema.md](./data-schema.md)(특히 §4.2, §4.3, §5, §7)를 따른다. 검증 결과는 `origin/reviews/{날짜}-{주제}/`에 범위별 보고서로 남기고, 발견 사항은 `[FIX]`(명백한 오류, 바로 수정), `[DECISION]`(사용자 판단 필요), `[NOTE]`(사소함)로 분류한다. 모든 발견 사항은 원본 파일과 인용 문구를 근거로 적는다.

## 1. 원본 대조

- 문항 수·번호: 원본 문항 수와 데이터 수가 같고, 번호 누락·중복이 없다. 입력하지 않은 문항(단답형 등)은 대응표와 작업 기록에 적는다.
- 발문·선택지·지문은 원본과 글자 단위로 같다(띄어쓰기, 기호, 따옴표 모양, 원본 오탈자 포함). 조용한 교정이 없다.
- 원본 밑줄·굵은 글씨(`않은`, `아닌` 등)가 `==강조==`로 빠짐없이 표시되어 있고, 원본에 없는 강조는 없다.
- 정답이 인쇄 정답(정답표·LMS 정답 표시)과 일치한다. 손으로 푼 결과가 다르면 정답은 그대로 두고 `※` 줄과 보고서에 적는다.
- ID ↔ 원본 파일 대응표가 `origin/reviews/`에 있다.

## 2. 풀이 가능성 (렌더링된 화면 기준)

- 발문이 가리키는 그림·표·코드·지문(`다음`, `위의`, `그림`)이 화면에 모두 나온다. 공통 지문은 필요한 모든 문항에 `passageRefs`로 연결되어 있고, 문항 하나만 무작위로 나와도 풀 수 있다.
- 이미지는 잘리지 않았고 읽을 수 있다. 가능하면 이미지 대신 diagram·data-table로 다시 그린다.
- 수식(`$`)·강조(`==`)·인라인 코드(`` ` ``)가 의도대로 렌더링된다. 코드형 `==`(`a == b`)는 강조로 오인되고 홀수 개면 빌드가 실패하므로 백틱으로 감싼다.
- 여러 줄 코드 선택지는 `|` 블록으로 써서 들여쓰기가 보존된다. 코드 지문은 `type: code`다.
- 백틱 쌍은 항상 인라인 코드로 렌더링되므로, 원본에 백틱 문자가 그대로 있으면 코드 지문이나 `cellFormat: code` 표에 넣는다. 표의 빈 칸은 `' '`(공백 한 칸)이다.
- 선택지 순서를 섞어도 문제가 성립한다. 이미지·diagram 선택지는 `text: ''`다.
- 다른 문항 번호를 참조하는 발문(`문제 15번 참조`)은 필요한 자료를 `passageRefs`로 함께 연결한다.

## 3. 정답 누출

- 이미지 `alt`, 파일명, 지문, 하이라이트가 정답이나 판단 핵심을 알려주지 않는다.
- 형제 문항(같은 지문·같은 강)의 해설이나 지문이 이 문항의 정답을 그대로 알려주지 않는다(피할 수 없는 경우는 NOTE).
- 한 선택지만 형태가 두드러지게 다르지 않다(원본이 그렇다면 그대로 두고 NOTE).
- 해설 문장이 발문이나 선택지 텍스트에 섞여 들어가지 않았다.

## 4. 해설

- 선택지마다 `선택지 N:` 줄이 있고 오답도 이유를 설명한다. "교재에 없음", "틀렸다"만 있는 공허한 해설이 없다. `핵심 개념:` 블록이 있다.
- 기술적으로 정확하다. 계산·코드 출력·논리·권한 등은 직접 다시 풀거나 실행해 확인한다(오답 선택지 해설의 역산 값 포함).
- 원본 해설의 오류를 옮기지 않았다. 원본 서술·인쇄 정답에 문제가 있으면 원본은 그대로 두고 해설에 `※` 줄로 표시한다([data-schema.md §7](./data-schema.md)).
- 해설 본문과 `※` 줄에서 선택지를 번호(`①`, `선택지 3과 같은`)로 가리키지 않고 내용으로 지칭한다.
- 데이터 작업 메모나 추측 표현("그대로 옮겼다", "~로 보인다")이 없다.
- 같은 과목의 다른 출처(기출·교재·워크북·강의)와 같은 개념을 서로 모순되게 설명하지 않는다. 용어 표기가 과목 안에서 통일되어 있다.

## 5. 메타데이터

- `subjectId`, `sourceId`, `kind`, `year`가 catalog와 일치하고 catalog에 출처가 등록되어 있다.
- ID 규칙([data-schema.md §4](./data-schema.md))을 따르고, syllabus가 있는 과목은 장 배정이 맞다(기출 `chapter`/`outdated`, 강의는 강 번호가 syllabus에 존재).
- ID 그룹이 장 번호가 아닌 워크북(C프로그래밍)이나 부록 장(시뮬레이션 워크북 10장)은 문제마다 `chapter`를 적는다.
- 태그·연도 등 부가 필드가 원본과 맞다.

## 6. 마무리

- `pnpm data:build`, `pnpm test`, `pnpm format:check`, `pnpm exec tsc --noEmit`이 통과한다. `pnpm data:build`의 `WARNING:`(참조되지 않는 지문)이 없는지 본다.
- 선택지 섞기를 켜고, 모바일 폭에서 이미지·코드·표가 들어간 문항을 몇 개 직접 확인한다.
- 한 세트에서 정답 번호 분포가 지나치게 몰리지 않았는지 본다(입력 오류 신호).
- [source-coverage.md](./source-coverage.md), `WORK.md` 작업 기록, 필요하면 [outdated.md](./outdated.md)를 갱신한다.
