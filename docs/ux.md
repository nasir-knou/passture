# UX

현재 구현된 주요 화면, 랜덤화 정책, 저장소 사용, 데이터 관리 흐름.

## 1. 주요 화면

### 1.1 홈

- 과목 카드 그리드
- 학기 필터: `전체 / 1학기 / 2학기`. 기본값은 항상 `전체`다(여러 과목의 자료가 있다는 것을 먼저 보여주기 위해 날짜 기준 기본값을 쓰지 않는다).
- 과목 카드에는 `1학기` 또는 `2학기` 배지, 출처 수, 출처 목록(`2019 기말 · 기출`)을 표시한다.
- 상단바: 문제 선택, 모의 시험, 학습 기록, 데이터 관리
- 과목 카드의 선택 버튼으로 해당 과목 선택 화면 진입

### 1.2 과목/문제 선택

- 과목 선택 (홈에서 진입 시 자동 선택)
- 학기 필터: `전체 / 1학기 / 2학기`
- 선택 화면 안에서 과목 select로 다른 과목 전환. 과목 옵션은 선택한 학기 필터에 맞춰 표시하고, `1학기 · 운영체제`처럼 학기와 과목명을 함께 표시한다.
- 홈에서 특정 과목으로 진입하면 해당 과목의 학기를 필터 기본값으로 사용한다.
- 과목 없이 진입하면(상단바 `문제 선택` 등) 접속 기기의 로컬 시간 기준으로 2월~7월은 1학기, 8월~1월은 2학기를 기본 필터로 선택하고, 그 학기에서 출처가 있는 첫 과목을 고른다. 학기 필터를 바꿀 때도 해당 학기의 첫 과목으로 이동한다. 선택한 학기는 URL의 `semester` 값(`all / 1 / 2`)으로 유지한다.
- 과목 select 옆에 선택 과목의 학습 상태(북마크 수, 오답 문항 수, 오답 누적 횟수, `오답 보기` 링크 → `#/history?filter=wrong&subject={subjectId}`)를 표시한다. 기록이 없으면 `풀이 기록 없음`을 표시한다.
- 선택된 과목의 출처 체크리스트 (다중 선택 가능, 기본 선택 없음)
  - 큰 분류는 `기출 / 교재 / 강의`만 사용하고, 출처마다 분류 배지를 표시한다.
  - 교재 분류 안에 `기본서 문제`, `워크북 문제`를 둔다.
  - 강의 분류 안에 `연습문제`, `특강 문제`를 둔다.
  - 기출 출처를 최신 연도순으로 먼저 보여주고, 나머지는 등록 순서대로 보여준다.
  - 출처명 옆에는 빌드된 문제 수를 `2019 기말 (25문제)` 형식으로 표시한다.
  - `문제 검색` 입력으로 출처명·분류·연도와 문제 본문·선택지·해설·문제 ID를 검색해 출처 목록을 거른다.
- 문제 범위:
  - 전체
  - 북마크만
  - 오답만
- 옵션:
  - 문제 순서: 기본 / 순서 무작위
  - 선지 순서: 기본 / 순서 무작위
- 선택 요약: 선택한 출처 수, 총 문항 수, 선택한 출처 칩
- 풀이 시작 버튼

### 1.2.1 챕터별 풀이

- `catalog.yaml`에 `syllabus`가 등록된 과목만 선택 화면에 `출처별 / 챕터별` 전환이 나타난다. 챕터별 모드 URL은 `#/select?subject={subjectId}&semester={학기}&mode=chapter`이다.
- 챕터별 모드는 출처 체크리스트 대신 교재 장 목록을 보여준다. 교재에 부 구분이 있으면(선형대수 Ⅰ–Ⅲ부) 부 단위로 묶고 `부 전체` 버튼을 제공한다. `전체 선택 / 전체 해제` 버튼도 있다.
- 장마다 `강의 N · 교재 N · 기출 N` 문제 수와, 그 장을 다루는 강 번호(`3–4강`)를 표시한다. 어떤 종류에도 문제가 없는 장은 비활성화한다.
- 문제 종류는 `강의 / 교재 / 기출` 체크박스로 고른다. 과목에 해당 종류의 출처가 아직 없으면 `(준비 중)`으로 비활성화한다.
- 문제 범위(전체/북마크만/오답만)와 문제·선지 순서 옵션은 출처별 모드와 같다.
- 문제 순서 `기본`은 장 순서 → 강의 → 교재 → 기출 → 출처 등록 순서 → 파일 내 문제 순서다.
- 교재 개정으로 현재 목차에 없는 기출(`outdated: true`)은 챕터별 풀이에서 제외하고, 제외된 문제 수를 안내한다. 연도별 풀이와 모의 시험에는 그대로 나온다.
- 풀이 화면과 결과 문제 카드의 출처 라벨에 `선형대수 - 2019 기말 · 4장`처럼 장을 함께 표시한다. 결과 화면에는 `장별 결과`(장별 정답률)를 추가로 보여준다.
- 결과 화면의 `오답만 / 북마크만 다시 풀기`는 챕터별 풀이에서 선택한 장·문제 종류를 유지한 채 범위만 바꾼다.
- 북마크·오답 기록은 출처별 풀이와 같은 문제 키를 쓰므로 두 모드에서 공유된다.

### 1.3 문제 풀이

- 상단바: 문제 선택, 모의 시험, 풀이, 결과, 데이터 관리 (결과 화면도 같다)
- 상단: 출처 라벨, 현재 문제/전체 문제 표시, 답안 체크 기준 진행률과 정답 확인 수, 문제·선지 순서 옵션 상태
- 문제 번호 지도:
  - 현재 문제
  - 답안 체크 안 함
  - 답안 체크함
  - 정답 확인함
  - 북마크 표시
  - 번호 클릭으로 해당 문제 이동
  - 기본은 현재 문제 주변 한 줄(26개)만 보여주고, `전체 보기 / 접기`로 전체 번호와 범례를 펼친다.
- 공통 지문이 있으면 문제 상단에 표시
- 공통 지문의 데이터 식별자(`passages.id`)나 내부 라벨은 화면에 표시하지 않는다.
- 텍스트 지문은 수식을 렌더링하고, 이미지 지문은 crop 이미지를 표시하며, diagram 지문은 구조화 데이터에서 도표를 렌더링한다.
- 문제 본문
- 첨부 이미지
- 선택지 목록 (복수 정답 문제는 체크박스, 나머지는 라디오. 선지 순서 옵션이 `순서 무작위`일 때만 섞는다)
- 문제 위 `이전 / 북마크 / 다음`, 문제 아래 `이전 / 정답 확인 / 다음` 버튼. 확인한 문제는 `다시 확인`으로 다시 채점할 수 있다.
- 정답 확인 후:
  - 정답·오답 표시 (선택지 색상)
  - 해설 영역 표시: 문제 키, 정답 번호(화면 표시 순서 기준), 해설
  - 해설의 `선택지 N:` 줄은 보기별로 `N번 (정답/오답)`과 함께, `핵심 개념` 블록은 따로 묶어 표시한다. `※`로 시작하는 줄은 해설 끝 별도 안내 블록에 한 줄씩 표시한다. 인라인 코드와 강조 표기는 [data-schema.md](./data-schema.md) 참고.
- 모든 문제에 답안을 체크하면 하단 `채점하기` 버튼 활성화. 채점하기는 정답 확인을 하지 않은 답안도 함께 채점하고 결과 화면으로 이동한다.
- 하단에 모든 문제에 1번 보기를 체크하는 `모든 답안 1번 체크` 버튼이 있다.

### 1.4 결과

- 총 문항, 응답, 정답, 정답률 카드
- 리포트: 정답률 막대와 정답 / 오답 / 미응답 수
- 출처별 결과(출처별 정답률), 챕터별 풀이면 장별 결과
- 문제별 정답 / 오답 / 미응답 지도
- 번호 클릭 시 해당 문제, 선택지, 정답/오답, 해설 표시 (`#/result?question={번호}`)
- 풀이로 돌아가기 / 오답만 다시 풀기 / 북마크만 다시 풀기 / 새 세션 시작
  - 다시 풀기는 이번 세션의 출처를 그대로 쓰고 범위만 `오답만`(`pt.wrongAnswers` 기준) 또는 `북마크만`으로 바꿔 새 세션을 만든다.

### 1.5 학습 기록

- URL: `#/history`
- 과거 `#/bookmarks` URL은 `#/history`로 이동한다.
- 설명: 북마크한 문제와 오답 문제를 모아두는 공간
- 요약: 전체, 북마크, 오답 문제 수
- 필터:
  - 기록 유형: 전체 / 북마크 / 오답 문제
  - 학기: 전체 / 1학기 / 2학기 (기본값 `전체`)
  - 과목: 전체 과목 / 개별 과목 (선택한 학기의 과목만)
  - 출처: 전체 출처 / 개별 출처
  - 필터 값은 URL의 `filter`, `semester`, `subject`, `source`로 유지한다.
- 모두 펼치기 / 모두 접기
- 문제 카드는 기본 접힘 상태:
  - 접힘: 문제 키, 과목/출처/분류, 북마크 배지와 `오답 N회` 배지, 문제 본문
  - 펼침: 지문, 선택지(정답 표시 없음), 북마크한 문제면 북마크 해제 버튼

### 1.6 데이터 관리

Passture는 별도의 서버/데이터베이스를 사용하지 않고 데이터를 로컬 브라우저에만 저장한다. 사용자별 북마크와 오답 기록은 자동 동기화되지 않으므로 사용자가 직접 JSON 파일로 내보내고 다른 기기에서 가져온다.

- 내보내기: 현재 `localStorage` 데이터를 JSON 파일로 다운로드
- 가져오기: 사용자가 선택한 JSON 파일을 검증 후 병합 또는 덮어쓰기
- 파일을 고른 뒤 `병합` 또는 `덮어쓰기` 버튼으로 방식을 직접 고른다 (충돌 여부를 따로 검사하지 않는다)
- 잘못된 JSON, 버전 불일치, 필수 필드 누락에 대한 오류 메시지 제공
- 현재 풀이 초기화: `sessionStorage`의 출처 선택, 챕터 선택, 범위/순서 옵션, 현재 풀이 세션 삭제
- 학습 기록 초기화: `localStorage`의 북마크와 오답 기록 삭제. 현재 풀이 초기화 항목도 함께 삭제
- 두 초기화 모두 확인 대화상자를 거친다. 모의 시험 설정·세션은 지우지 않는다.

### 1.7 모의 시험

- 상단바 메뉴와 `#/mock-exam`, `#/mock-exam/test`, `#/mock-exam/result` 라우트가 존재한다.
- 저장된 문제를 유사 기말 시험 환경에서 타이머와 함께 푸는 방식이다.
- 문제는 기존 YAML/JSON으로 빌드된 저장 문제 풀에서 구성한다.
- 학기 필터: `전체 / 1학기 / 2학기`
- 접속 기기의 로컬 시간 기준으로 2월~7월은 1학기, 8월~1월은 2학기를 기본 필터로 선택한다.
- 과목은 1~3개까지 선택할 수 있고, 시험 시간은 과목 수 × 25분으로 계산한다 (`전체 풀기`여도 같다).
- 과목별로 하나의 출처만 선택할 수 있다(기본 선택 없음, 기출 최신 연도순으로 먼저 표시). 여러 과목을 선택해도 각 과목은 독립된 단일 출처에서 문제를 가져온다.
- 과목별 문항 구성: `무작위 25문제`(기본) / `전체 풀기`
- 문제 순서 / 선지 순서: 기본 / 순서 무작위 (기본값 `기본`)
- 설정 화면에 선택 과목 수, 시험 시간, 예상 시작·종료 시각, 과목별 문항 구성 요약을 표시한다.
- `무작위 25문제`에서 25문항 이하인 출처는 그대로 사용한다. 기출 출처가 25문항보다 많으면(예: 35문항) 무작위로 25문항을 추출한다.
- 교재/워크북/강의/특강 출처는 문제 ID의 첫 숫자 그룹을 기준으로 전체 그룹 범위를 파악한 뒤 25문항을 균등 분포로 추출한다. 예: 최대 그룹이 `07`이면 각 그룹에서 3~4문항, 최대 그룹이 `11`이면 2~3문항, 최대 그룹이 `15`이면 1~2문항을 뽑는다.
- 문제 수가 부족한 그룹이 있으면 가능한 만큼 뽑고, 부족분은 아직 선택되지 않은 전체 후보에서 무작위로 채워 최종 25문항을 맞춘다.
- 풀이 중에는 시험 시간(시작~종료 시각), 남은 시간(5분 이하 경고), 과목 탭(과목별 응답 수), 답안표, 책갈피를 보여준다.
  - 시험 시각은 시험 화면에 들어가 세션을 만든 시점부터 계산한다. 진행 중 세션은 `sessionStorage`에 남아 새로고침해도 이어지고, 남은 시간은 시작 시각 기준으로 계속 줄어든다.
  - 답안표는 문항마다 고른 보기를 화면 표시 순서 번호(①~)로 보여주고, 행을 누르면 해당 문항으로 이동한다.
  - 책갈피는 시험 안에서만 쓰는 표시로, 학습 기록의 북마크(`pt.bookmarks`)에는 저장하지 않는다.
  - 글자 크게 / 글자 작게, 세로 스크롤 ↔ 한 문제씩 보기 전환을 제공한다. 한 문제씩 보기에서는 이전/다음 버튼과 `현재 번호 / 전체` 표시가 나오고, 과목 탭을 바꾸면 그 과목의 1번부터 한 문제씩 보여준다.
- `시험실 퇴실` 확인 모달 또는 시간 종료 시 시험을 종료하고 `#/mock-exam/result`로 이동한다. 풀이 중 다른 라우트로 이동하면 확인 후 시험을 종료하고, 새로고침·탭 닫기에는 브라우저 이탈 경고를 띄운다.
- 결과 화면에는 시험형 결과 리포트를 표시한다.
  - 전체 총 문항, 정답, 전체 정답률
  - 과목 탭별 총 문항, 응답, 정답, 정답률 카드와 문제별 정답 / 오답 / 미응답 지도, 문제·선택지·정답·해설
  - 채점은 `choice.id` 기준이며, 모의 시험 결과는 오답 기록(`pt.wrongAnswers`)에 반영하지 않는다.
  - `새 모의 시험` / `세션 초기화`

### 1.8 스크롤 정책

- 라우트 이동 시 기본적으로 브라우저 스크롤 위치를 유지한다.
- 문제 선택 화면(`/select`)에 새로 진입할 때만 페이지 최상단으로 이동한다.

## 2. 랜덤화 정책

- 문제 순서: 사용자가 `순서 무작위`를 선택하면 풀이 세션 생성 시 Fisher-Yates 셔플로 섞는다. 기본값은 데이터 순서다.
- 선택지 순서: 사용자가 `순서 무작위`를 선택하면 세션 생성 시 섞는다. 기본값은 데이터 순서다. 정답 판정은 표시 순서가 아니라 `choice.id` 기준으로 한다. 화면의 보기 번호, 해설의 정답 번호·`N번 (정답/오답)`, 모의 시험 답안표 번호는 모두 표시 순서 기준이다.
- 모의 시험도 같은 문제·선지 순서 옵션을 따로 가진다. `무작위 25문제` 추출은 순서 옵션과 관계없이 항상 무작위다.
- 시드: 아직 지원하지 않는다.
- 같은 세션 내에서는 순서를 유지한다. 세션은 `sessionStorage`에 저장되며, 같은 출처/범위/순서 옵션이면 새로고침 후에도 이어진다.

## 3. localStorage 저장 항목

키 prefix는 `pt.`로 통일한다. 영구 사용자 데이터는 `localStorage`, 현재 풀이 세션과 선택 옵션은 `sessionStorage`에 저장한다.

```text
localStorage:
pt.bookmarks       # string[] (복합 키 배열)
pt.wrongAnswers    # Record<복합키, { wrongCount, lastWrongAt }>

sessionStorage:
pt.selectedSources # 현재 선택한 출처 배열
pt.chapterSelection # 챕터별 풀이 선택 { subjectId, chapters, categories }. 있으면 챕터별 세션으로 풀이한다
pt.practiceScope   # all | bookmarked | wrong
pt.practiceOptions # questionOrder / choiceOrder
pt.currentSession  # 진행 중 풀이 세션 스냅샷
pt.mockExamConfig  # 모의시험 설정
pt.mockExamSession # 진행 중 모의시험 세션 스냅샷
```

일부 풀이 화면 UI 상태는 기존 호환 키인 `passture.questionMapExpanded`, `passture.quiz.scrollY`를 `sessionStorage`에 저장한다.

오답 기록은 풀이 세션에서 문제를 처음 채점(정답 확인 또는 채점하기)할 때 틀리면 `wrongCount`를 1 올리고 `lastWrongAt`을 갱신한다. 같은 세션에서 다시 확인하거나 나중에 맞혀도 기록을 줄이거나 지우지 않는다.

`pt.bookmarks` 예시:

```json
["operating-systems:past-exams-2019:e19-01", "algorithms:workbook:b03-07"]
```

`pt.wrongAnswers` 예시:

```json
{
  "operating-systems:past-exams-2019:e19-01": {
    "wrongCount": 2,
    "lastWrongAt": "2026-05-06T12:30:00.000Z"
  }
}
```

사용자 설정, 자동 북마크는 아직 구현하지 않았다.

복합 키 형식과 식별자 규칙은 [data-schema.md §4](./data-schema.md) 참고.

## 4. 백업: 내보내기

내보내기 버튼을 누르면 현재 브라우저의 사용자 데이터를 하나의 JSON 파일로 생성한다.

파일명 예시:

```text
passture-user-data-20260506-010203.json
```

파일명의 시각은 UTC 기준이다.

내보내기 데이터 예시:

```json
{
  "app": "passture",
  "version": 1,
  "exportedAt": "2026-05-06T12:50:00.000Z",
  "bookmarks": ["operating-systems:past-exams-2019:e19-01"],
  "wrongAnswers": {
    "algorithms:workbook:b03-07": {
      "wrongCount": 2,
      "lastWrongAt": "2026-05-06T12:40:00.000Z"
    }
  }
}
```

## 5. 백업: 가져오기

가져오기는 사용자가 선택한 JSON 파일을 브라우저에서 읽고 검증한 뒤 `localStorage`에 반영한다.

방식:

- 병합: 기존 데이터를 유지하면서 가져온 데이터를 추가한다.
- 덮어쓰기: 기존 데이터를 삭제하고 가져온 데이터로 교체한다.

병합 규칙:

- 북마크는 중복 제거 후 합친다.
- 오답 기록은 같은 키가 있으면 `wrongCount`는 큰 값, `lastWrongAt`은 더 최근 값을 사용한다.
- 알 수 없는 문제 키는 삭제하지 않고 보존한다 (이후 데이터 추가/복구 가능성).

## 6. 백업: 검증 규칙

가져오기 파일은 최소한 다음 조건을 만족해야 한다.

- 최상위 `app` 값이 `"passture"`
- `version`이 지원 가능한 버전
- `exportedAt`이 비어 있지 않은 문자열
- `bookmarks`가 문자열 배열
- `wrongAnswers`가 객체이고, 각 항목의 `wrongCount`는 0 이상의 숫자, `lastWrongAt`은 비어 있지 않은 문자열
- 문제 키는 `{subjectId}:{sourceId}:{questionId}` 형식 (`questionId`는 `e19-01`처럼 영문 소문자 1자 + 두 자리 + `-` + 두 자리)

검증에 실패하면 `localStorage`를 변경하지 않고 오류를 표시한다.
